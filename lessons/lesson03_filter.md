# 第 3 课：过滤器与多节点通信

> 对应源码: src/can_dump.c
> 学习目标: 掌握 CAN_RAW_FILTER 内核过滤，理解多节点通信模式

## 1. 什么是过滤器？

CAN 总线上所有节点都能收到所有帧（广播）。
但很多时候我们只关心某些 ID 的数据（比如只要发动机转速 0x0C4）。

**过滤器**就是在内核里提前筛掉不关心的帧，只把匹配的帧送到用户程序。
好处：省 CPU、省内存拷贝、程序逻辑更简单。

## 2. 三种过滤方式对比

| 方式 | 位置 | 开销 | 灵活度 |
|------|------|------|--------|
| 不设过滤 | 无 | 高（所有帧都到用户态） | 最灵活 |
| 内核过滤 (CAN_RAW_FILTER) | 内核 | 低 | 中（基于 ID+Mask） |
| 用户态过滤 (代码 if) | 用户程序 | 中 | 最高 |

推荐：**先用内核过滤减负载，再在用户态做精细逻辑判断。**

## 3. 内核过滤器实现

```c
struct can_filter rfilter[1];
rfilter[0].can_id   = 0x123;          // 想要匹配的 ID
rfilter[0].can_mask = CAN_SFF_MASK;   // 掩码: 1=必须匹配, 0=忽略

setsockopt(s, SOL_CAN_RAW, CAN_RAW_FILTER, &rfilter, sizeof(rfilter));
```

### 掩码原理

```
要匹配的 ID:  0x123  =  0001 0010 0011
掩码:        0x7FF  =  1111 1111 1111   (全部必须匹配)

收到的帧:    0x123  → 匹配 ✅
收到的帧:    0x124  → 不匹配 ❌
```

```
要匹配的 ID:  0x100  =  0001 0000 0000
掩码:        0x7F0  =  1111 1111 0000   (高 7 位必须匹配)

收到的帧:    0x100 ~ 0x10F  → 全部匹配 ✅  (一组!)
收到的帧:    0x110         → 不匹配 ❌
```

## 4. 多节点通信模式

### 4.1 一主多从 (最常见的车载架构)

```
主控 (ID=0x001)
  ├── 传感器A (只发 ID=0x100, 只收 ID=0x001)
  ├── 传感器B (只发 ID=0x200, 只收 ID=0x001)
  └── 执行器C (只发 ID=0x300, 只收 ID=0x001)
```

每个节点都在看总线，但**只处理自己关心的 ID**。

### 4.2 命令 / 响应模式

```
主控发送: 0x001 数据: [cmd=0x01 参数...]   → 请求传感器A汇报
传感器A:  收到 0x001 后回复 0x100 数据: [当前温度]
```

示例练习：
```bash
# 终端1: 模拟传感器A, 监听命令 + 回复
./can_dump -i vcan0 -f 0x001     # 传感器只听 0x001

# 终端2: 模拟主控, 发命令
./send -i vcan0 -id 0x001 -d 01  # 发命令

# 终端3: 旁路监听全部
./can_dump -i vcan0
```

### 4.3 跨接口通信 (vcan0 ↔ vcan1)

```bash
# 桥接两个虚拟接口 (需要 root)
sudo ip link add vcan0 type vcan && sudo ip link set up vcan0
sudo ip link add vcan1 type vcan && sudo ip link set up vcan1
sudo ip link set vcan1 master vcan0   # vcan1 成为 vcan0 的从接口
```

之后 vcan0 上的帧也会出现在 vcan1 上。
